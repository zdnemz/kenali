## 1. Goal and pass criteria

From `roadmap.md` P0-S3 and `context_pack.md` §9: prove the auth-pipe contract end to end between
the thin CP and the SYSTEM service — SYSTEM-only DACL `D:P(A;;GA;;;SY)`, `FIRST_PIPE_INSTANCE`,
remote-client rejection, server-PID anti-squatting, bidirectional PID verification, one-shot
nonce-echoed secret release within **≤ 3 s**, bounded timeouts and strict size caps.

Pass conditions (all OWNER-run in the VM):
1. `\\.\pipe\kenali.auth` is created with SDDL `D:P(A;;GA;;;SY)` and `FILE_FLAG_FIRST_PIPE_INSTANCE`
   — a second creation attempt fails (no squatting race).
2. Remote clients are rejected (`PIPE_REJECT_REMOTE_CLIENTS`).
3. The server verifies the client PID: client image path is `%SystemRoot%\System32\LogonUI.exe` in
   the **console session**; a non-LogonUI client is rejected.
4. The client verifies the server PID against the SCM PID for `KenaliSvc` — a squatter pipe is
   rejected (bidirectional PID verification).
5. Message mode is in force; `AUTH_CONNECT_TIMEOUT = 200 ms` gates connect and
   `AUTH_ATTEMPT_TIMEOUT = 6 s` gates the response exchange — no unbounded wait.
6. A `Verified` response whose echoed nonce does not match the `BeginAttempt` nonce is rejected.
7. The password is released **only** to the pipe instance/nonce that started the attempt, within
   **≤ 3 s** of the decision, and is zeroized on all paths. It is never logged, never in a `String`.
8. Message cap ≤ 4096 B is enforced; an oversized or malformed message is rejected.
9. A `PROTO_VERSION` mismatch is rejected at `Hello`.

## 3. Offline-verified facts

These are **(a) OFFLINE FACTS** — from the docs / committed client code, not runtime observations.

### 3.1 Pipe identity and DACL (`context_pack.md` §9; `pipes.rs`)
- Path: `\\.\pipe\kenali.auth` — committed as `kenali_winapi::pipes::AUTH_PIPE_PATH`
  (`"\\\\.\\pipe\\kenali.auth"`, doubled backslashes in Rust literals). The server must **reuse**
  this constant; do not redefine.
- SDDL: `D:P(A;;GA;;;SY)` — SYSTEM only, committed as `AUTH_PIPE_SDDL`. Reuse it. This is the name
  of the security contract; a VSA outcome from P0-S2/U10 would change it (**VERIFY**).
- Create flags (server, planned `pipe_server::create_server_pipe`): `FILE_FLAG_FIRST_PIPE_INSTANCE`,
  overlapped where available, **message mode**, `PIPE_REJECT_REMOTE_CLIENTS`, small max instances.
  `FIRST_PIPE_INSTANCE` makes a second creation fail — the anti-squatting primitive.
- Create flags (client, `pipes.rs::connect`): `WaitNamedPipeW` bounded by `AUTH_CONNECT_TIMEOUT`,
  `CreateFileW` with `GENERIC_READ | GENERIC_WRITE`, `FILE_FLAG_WRITE_THROUGH` (synchronous), then
  `SetNamedPipeHandleState(..., PIPE_READMODE_MESSAGE, ...)`.

### 3.2 Bounded timeouts and caps (`pipes.rs`; `context_pack.md` §8)
- `AUTH_CONNECT_TIMEOUT = Duration::from_millis(200)` — gates `WaitNamedPipeW`.
- `AUTH_ATTEMPT_TIMEOUT = Duration::from_secs(6)` — gates the response wait via `PeekNamedPipe`
  polling against an `Instant` deadline (no unbounded blocking wait).
- `MAX_CONTROL_BYTES = 4096` — auth/control message cap; the client rejects an encoded request over
  the cap and decodes the response under the same cap.
- Every wire buffer (request and the one-shot `Verified.secret`) is a `Zeroizing<Vec<u8>>` and is
  wiped on all paths, including errors.

### 3.3 Bidirectional PID verification and anti-squatting (`context_pack.md` §9)
- **Client verifies server:** `GetNamedPipeServerProcessId` must equal the PID the SCM reports for
  `KenaliSvc` (`service_pid(KENALI_SERVICE_NAME)` in `pipes.rs`) — defeats pipe squatting.
- **Server verifies client (planned `pipe_server::verify_peer_pid` / `client_pid`):** use
  `GetNamedPipeClientProcessId`, then confirm the image path is `%SystemRoot%\System32\LogonUI.exe`
  in the console session; reject any other client.
- Handshake rejects a `PROTO_VERSION` mismatch; `Response::Verified` with an echoed nonce that does
  not match the `BeginAttempt` nonce is rejected (`PipeError::NonceMismatch`).

### 3.4 One-shot secret release (`context_pack.md` §2.9, §9; `pipes.rs` doc)
- The password is released **only** to the pipe instance and nonce that began the attempt, within
  **≤ 3 s** of the auth decision. The ≤ 3 s lifetime is a **service-side property** documented here
  (the client does not enforce it — see `pipes.rs` module doc); the OWNER measures it in §4.
- One submit per attempt (`context_pack.md` §2.8); failure statuses (wrong password / lock-out /
  expired / must-change) disable face unlock and never retry (`context_pack.md` §3.2).
- `PipeError` wording is generic: no secret / password / nonce in any error string.

### 3.5 Planned server seam (Wave-3 plan — may not exist yet)
`kenali_winapi::pipe_server` (W3-05) is **planned** with:
- `create_server_pipe(path: &str, sddl: &str) -> Result<WinHandle, PipeError>` — sets
  `FIRST_PIPE_INSTANCE`, rejects remote clients.
- `accept_client(handle: WinHandle, deadline: Instant) -> Result<WinHandle, PipeError>` — bounded
  `ConnectNamedPipe`.
- `verify_peer_pid(handle: WinHandle, expected_pid: u32) -> Result<(), PipeError>` and
  `client_pid(handle: WinHandle) -> Result<u32, PipeError>`.
The accept loop `kenali_service::pipe_loop::serve_auth_pipe` (W3-08) wires these to policy/state.
These are plans, not verified code; runtime behavior is **VERIFY**.

## 4. Procedure — exact manual VM steps (OWNER only)

These are **(b) OWNER MANUAL STEPS**, run by hand in the VM after the checkpoint. The agent runs none.

1. **Prepare the VM.** Checkpoint; record §2 rows; keep a second local admin with a password.
2. **Build + install.** Build the CP (`kenali-cp`, W2-03) and `kenali-svc` (W3-05/W3-08) for MSVC;
   install in the VM via `cargo xtask install --vm` (`KENALI_ALLOW_INSTALL=1`). Confirm
   `sc queryex KenaliSvc` gives the SCM PID and the service account is SYSTEM (or the VSA chosen in
   P0-S2 — if VSA, revisit the SDDL per §3.1).
3. **Confirm the DACL and FIRST_PIPE_INSTANCE.** With the service running, inspect the pipe's SDDL
   and confirm `D:P(A;;GA;;;SY)`. From an elevated PowerShell attempt to create a second instance of
   `\\.\pipe\kenali.auth` and confirm it fails (`ERROR_ACCESS_DENIED` / instance-exists) — proving
   `FIRST_PIPE_INSTANCE`.
4. **Confirm remote-client rejection.** From a *different* machine / host on the network attempt to
   open the pipe; confirm it is unreachable (`PIPE_REJECT_REMOTE_CLIENTS`). Record the result.
5. **Confirm server-PID anti-squatting (client side).** In a controlled VM test, stand up a pipe at
   the same name from a process whose PID is **not** the SCM PID for `KenaliSvc` and confirm the CP
   client rejects it (`IdentityMismatch`). Do not leave the squatter running.
6. **Confirm server verifies client PID.** From a non-LogonUI process attempt the handshake; confirm
   the service rejects it (client image path not `%SystemRoot%\System32\LogonUI.exe`). Then run the
   real CP in LogonUI and confirm it is accepted.
7. **Confirm message mode + bounded waits.** Observe one `Hello` exchange: message-mode framing,
   connect bounded by **200 ms**, response by **6 s**. Simulate an unresponsive server and confirm
   both timeouts fire (no hang). Confirm oversized (> 4096 B) and `PROTO_VERSION`-mismatched messages
   are rejected.
8. **Confirm nonce echo + one-shot release.** Run a real attempt: `BeginAttempt { nonce }` →
   service decision → `Verified { nonce, secret }`. Confirm the echoed nonce matches; confirm a
   tampered nonce is rejected. Confirm the secret is released once, to that instance only, and that
   a replay is rejected.
9. **Measure password-release latency.** Timestamp the auth decision and the moment the `Verified`
   secret is available to the CP; confirm the delta is **≤ 3 s** (target well under). Record p50/p95
   in §5.
10. **Confirm hygiene + fallback.** Confirm no secret/nonce in service/CP logs or errors; the normal
    password/PIN tile still works; after a failure status face unlock disables and never retries.
11. **Reset.** Stop the squatter/test helpers; leave the VM with the service and CP installed
    correctly.
